# Система онлайн-записи для шиномонтажа: системный анализ

Учебный проект по системной аналитике. Кейс: небольшой шиномонтаж (2 бокса, один салон) ведёт записи в тетради и теряет клиентов. Нужно описать систему, которая решает эту проблему.

> Это учебный кейс. Заказчик вымышленный, цифры (количество боксов, записей в день) взяты как допущения и в реальном проекте уточняются у владельца. Для этого подготовлен список вопросов для интервью.

## Проблема

- Двойные записи на одно время и простой боксов.
- Очереди в сезон, часть клиентов уезжает.
- Расчёты и итоги за месяц делаются вручную на бумаге.

## Решение

Сайт с базой данных: онлайн-запись на свободное время, расписание боксов, список ожидания, учёт выполненных работ. Расчёты выручки ведутся в Excel по выгруженным данным.

## Ключевые допущения

Один салон, 2 бокса, работа с 8:00 до 19:00, около 10 записей в день. Все записи (сайт, звонок, визит) идут через единое расписание. Обзвон списка ожидания при отмене делает администратор.

## Стек: что за что отвечает

Стек предложен как рекомендация. В реальном проекте его выбирает команда.

| Часть системы | Технология | За что отвечает |
|---------------|-----------|-----------------|
| Интерфейс | HTML, CSS, JavaScript | Сайт записи для клиента, экраны администратора и владельца в браузере |
| Сервер | Python (FastAPI или Flask) | Логика: проверка слота, расчёт цены, запрет двойных записей, права по ролям, выгрузка в CSV |
| База данных | PostgreSQL (или SQLite для старта) | Хранит клиентов, машины, услуги, боксы, записи и список ожидания |
| Вход и права | Логин, пароль, роли | Доступ администратора и владельца, клиент видит только публичную часть |
| Расчёты | Excel | Формулы по данным, выгруженным из системы в CSV |

Пример работы: клиент выбирает время на сайте, сервер проверяет в базе, свободен ли бокс, создаёт запись, администратор видит её в расписании.

## Расшифровка обозначений

| Обозначение | Что значит |
|-------------|-----------|
| BR | Business Requirement, бизнес-требование: зачем бизнесу система |
| US | User Story, пользовательская история: «Как [роль], я хочу [действие], чтобы [польза]» |
| FR | Functional Requirement, функциональное требование: что система делает |
| NFR | Non-Functional Requirement: как система работает (скорость, безопасность) |
| MVP | Минимальная первая версия |
| PK / FK | Первичный ключ (уникальный id) / внешний ключ (ссылка на другую таблицу) |
| ER | Схема таблиц базы данных и связей между ними |
